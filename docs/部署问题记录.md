## 一、遇到的问题 1：免费平台要求绑定支付方式

### 现象

按 `DEPLOY.md` 的「方式 A：单服务部署到 Render」操作时，在 Render 创建 Web Service 的阶段被要求**绑定支付方式（绑卡）**；改用 Railway 也一样要求绑定支付方式。

### 影响

- 无法完成 Render / Railway 上的部署
- 项目本身没有任何问题，纯粹是平台侧的风控/计费门槛

### 当时的判断

验收只要求「线上可操作页面 + 三态截图 + 一次真实问题记录」，
其中「线上可操作」并不强制必须是某个平台，因此优先选择一条**零注册、零绑卡**的路径先把线上跑通。

## 二、解决方案：Cloudflare 临时隧道

### 命令

```powershell
# 安装（一次即可）
winget install --id Cloudflare.cloudflared -e

# 本地服务先起来
node app.js

# 另开终端，开隧道
cloudflared tunnel --url http://localhost:3000
```

### 过程中遇到的第二个小问题：QUIC 不通，自动降级

首次连接时 cloudflared 输出：

```
INF | WARNING: Allow outbound QUIC traffic on port 7844 or use HTTP2.
INF | SUMMARY: Environment ready with degraded transport. cloudflared will proceed using 'http2'.
```

**原因**：本机网络对 UDP 7844 端口（QUIC）不友好。

**处理**：不需要手动干预，cloudflared 会自动降级到 HTTP/2 传输，隧道照常可用。
如果希望显式指定，可用：

```powershell
cloudflared tunnel --protocol http2 --url http://localhost:3000
```

## 四、遇到的问题 2：git push 连接被重置

### 报错原文

```
fatal: unable to access 'https://github.com/grarew/Web_manage.git/':
Recv failure: Connection was reset
```

### 定位

- `git commit` 本地成功，说明改动没问题
- 仅 `git push` 失败，属于网络层问题（到 GitHub 的连接被重置），不是权限或仓库问题

### 解决

调大 HTTP 缓冲区并设置低速断开阈值后重试，一次成功：

```powershell
git -c http.postBuffer=524288000 push origin main --no-progress
```

结果：

```
88a06aa..9db261b  main -> main
```

## 五、经验总结

| 问题类型 | 典型报错 | 排查入口 |
|---|---|---|
| 平台门槛 | 要求绑定支付方式 | 属平台策略，换平台或换方案 |
| 网络传输 | `QUIC connection failed` | cloudflared 会自动降级 http2，可加 `--protocol http2` |
| Git 推送 | `Recv failure: Connection was reset` | 调整 `http.postBuffer` 后重试，或换网络 |
| 跨域 | `blocked by CORS policy` | 见 [CORS问题记录.md](CORS问题记录.md) |

### 隧道方案的适用边界

- ✅ 适合：课堂演示、快速验收、临时公网访问
- ❌ 不适合：长期运行（进程/电脑关掉即失效、域名会变）
- 长期方案：自己的云服务器（`DEPLOY.md` 方式 C）或阿里云函数计算（方式 D）
